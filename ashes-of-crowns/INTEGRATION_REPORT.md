# گزارش یکپارچه‌سازی ASHES OF CROWNS

## نتیجهٔ کار

یک Runtime اصلی ساخته شده که شش ماژول را با یک Event Bus مشترک متصل می‌کند. مسیرهای اصلی شروع بازی، ساخت مرحله، حرکت و مبارزه، تعامل با NPC، دیالوگ، مأموریت، لوت، مهارت، فروشگاه، ساخت تجهیزات، checkpoint و ذخیره/بارگذاری در کد اصلی به هم وصل شده‌اند.

## اتصال ماژول‌ها

| ماژول | اتصال انجام‌شده |
|---|---|
| Player | کنترلر آرن، فیزیک Phaser، دوربین، ورودی کیبورد و ورودی لمسی UI |
| Combat | دشمن‌ها و باس‌ها از دادهٔ World، برخورد با زمین و خطرها، ضربه و مهارت‌ها، کمک همراهان |
| World | ساخت ۱۳ مرحله از داده‌ها، NPCها، اشیای قابل تعامل، آیتم‌های جمع‌آوری، خروجی مراحل، دیالوگ و مأموریت |
| RPG | آمار آرن، XP، لوت، تجهیزات، مهارت‌ها، hotbar، مصرفی‌ها، فروشگاه و crafting |
| UI | منوی شروع، HUD، منوهای موجودی/مهارت/نقشه/مأموریت، دیالوگ، پایان، کنترل لمسی و backend adapter |
| Persistence | IndexedDB، سه اسلات دستی، autosave، ذخیرهٔ World/RPG، موقعیت و جان آرن، checkpoint و تنظیمات |

## قراردادهای مهمی که در Runtime تطبیق داده شدند

- همهٔ ماژول‌ها از `game.events` به‌عنوان Event Bus مشترک استفاده می‌کنند.
- رویدادهای کشتن دشمن به World و RPG می‌رسند؛ شکست باس به World، RPG و Persistence می‌رسد.
- پاداش‌های World به XP، طلا و موجودی RPG تبدیل می‌شوند.
- تکمیل مأموریت World به رویداد تکمیل مأموریت RPG و درخواست autosave تبدیل می‌شود.
- پرچم‌های داستانی World به RPG منتقل می‌شوند تا recipeها و قابلیت‌های وابسته به story flag قفل‌گشایی شوند.
- پایان داستان با اسلایدهای مخصوص همان پایان به صفحهٔ پایان UI منتقل می‌شود؛ سیستم unlock در RPG نیز فعال می‌شود. دکمهٔ New Game+ به چرخهٔ NG+ در RPG وصل شده و World را برای دور تازه بازنشانی می‌کند، درحالی‌که پیشرفت‌های قابل‌حفظ RPG باقی می‌مانند؛ دشمنان دورهای بعدی نیز با ضریب سلامت/آسیب/پاداش مقیاس می‌شوند.
- درخواست کمک همراه از Combat به World می‌رود و action برگشتی همراه در Combat اجرا می‌شود؛ همراهان عضو گروه نیز به‌صورت actor دنبال‌کننده نمایش داده می‌شوند.
- ورودی لمسی UI و ورودی کیبورد در `InputBridge` به یک InputFrame واحد برای Player تبدیل می‌شوند؛ بنابراین کنترل لمسی دوباره‌کاری یا دو بار اجرا نمی‌شود. دکمه‌های ضربهٔ سنگین و دفاع نیز به ردیف کنترل‌های لمسی اضافه شدند تا با خوشهٔ حمله/پرش هم‌پوشانی نداشته باشند.
- دادهٔ JSON مربوط به World و RPG در Save به‌صورت رشتهٔ JSON نگهداری می‌شود؛ مختصات، جان، مانا، استقامت، منطقه و مرحله نیز جداگانه ثبت می‌شوند.

## آزمون‌هایی که واقعاً اجرا شدند

| بخش | نتیجه |
|---|---:|
| Player core | ۳۲ تست موفق |
| World / Story | ۱۰۲ assertion موفق، صفر خطا |
| RPG | ۸۵ تست موفق |
| Combat core | ۱۵ تست موفق |
| Persistence | ۳۸ تست موفق |
| UI | TypeScript strict typecheck موفق |
| اتصال بین‌ماژولی | Integration smoke موفق: World ↔ Combat ↔ RPG ↔ Persistence |

جمع تست‌های headless ماژول‌ها: **۱۷۰ تست Node و ۱۰۲ assertion مربوط به World**، به‌علاوهٔ typecheck رابط کاربری و smoke test اتصال.

## مواردی که هنوز تأیید نشده‌اند

1. محیط اجرای فعلی به اینترنت npm دسترسی نداشت و Phaser/Vite در آن نصب نبود؛ بنابراین `npm install`، build واقعی Vite با تایپ‌های رسمی Phaser و اجرای مرورگر از داخل این محیط انجام نشد. Typecheck لایهٔ Runtime با shim موقت برای Phaser انجام شد؛ این جایگزین build واقعی نیست.
2. آزمون end-to-end با Chromium و تست واقعی روی گوشی Android انجام نشده است.
3. فایل‌های ماژول‌ها sprite نهایی، پس‌زمینهٔ نهایی و موسیقی/افکت کامل نداشتند. فعلاً از شکل‌ها و بافت‌های procedural و صداهای سادهٔ تولیدشده در مرورگر استفاده می‌شود.
4. متن دیالوگ‌های داستانی World عمدتاً انگلیسی است؛ رابط کاربری فارسی/انگلیسی و پیش‌فرض آن فارسی شده، اما ترجمهٔ کامل ۴۵ درخت دیالوگ در این مرحله انجام نشده است.
5. تعادل سختی، مسیر کامل هر شش فصل و پنج پایان باید در اجرای واقعی بازی و playtest بررسی شود؛ تست‌های World و RPG صحت منطق داده‌ها را بررسی می‌کنند، نه تجربهٔ بازی در مرورگر.

## دستور اجرای نهایی پس از نصب وابستگی‌ها

```bash
npm install
npm run build
npm run dev
npm run test:core
```

برای Cloudflare Pages، فرمان build برابر `npm run build` و پوشهٔ خروجی `dist` است.
